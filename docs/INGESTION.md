# Durable ingestion and accounting (R1-02)

Decision recorded 2026-09-11 before implementation. This contract extends [ARCHITECTURE.md](ARCHITECTURE.md) and [TELEMETRY.md](TELEMETRY.md). The bounded implementation now has local evidence in [VALIDATION.md](VALIDATION.md); broader source, migration and operating gates remain open.

## Identity and deployment

The 2026-09-12 native intake in [CAPTURE.md](CAPTURE.md) reuses this ledger through a durable numeric inbox. A database has one persisted source mode: `langfuse` or `direct`. Worker writes claim/touch that binding transactionally; incompatible processes cannot adopt the same initially empty database. Existing unbound Langfuse deployments adopt a Langfuse binding without rewriting their measurements. Use a fresh isolated database for direct mode; do not remove binding/ledger state to bypass migration checks. Direct processing drains a persisted receipt-sequence cutoff and provides no upstream pagination or source watermark.

The worker owns one configured connection (`GUARDIAN_CONNECTION_ID`, default `primary`). Keep this value stable during credential rotation; assign a new connection when changing upstream projects. Authorization still belongs to the single-tenant deployment. Source project attributes do not authorize access. Observation identity is a canonical hash of connection, source, project, trace and observation IDs. Missing observation IDs are rejected rather than invented from trace IDs. API version is not part of identity.

MongoDB must support multi-document transactions (replica set). There is no production mock or nontransactional fallback. Every write transaction, including worker health, mutates the connection lease while checking its owner, monotonically increasing epoch and validity. A stale worker cannot commit after takeover. Source HTTP and detector evaluation run outside retryable transaction callbacks. The installed Motor 3.3.1 commit-context behavior required an explicit transaction runner: unknown commit acknowledgements retry the same transaction; transient errors retry its body; a monotonic 30-second budget limits retry admission. Individual driver operations remain subject to their timeouts.

## Source progress and durable work

V2 ingestion reads one complete page at a time. A traversal pins its start/end, API version, normalization version and page size. The worker has a bounded number of pages per poll and resumes the stored cursor on the next poll. A valid envelope has one accepted or quarantined disposition per source row, including duplicates. A malformed envelope never advances progress. Cursor hashes detect cycles without exposing cursor contents. A provider-rejected continuation cursor may restart the same fixed window once, retaining the query fingerprint; identity deduplication makes replay safe. A query fingerprint mismatch blocks for explicit reconciliation instead of adopting a changed host, public-key scope or normalizer.

Each page transaction commits ledger changes, content-free quarantine records, pending processing work, a page receipt and the continuation together. The source watermark advances only after the last page is durable. It is separate from processing completion. An interruption after ingestion leaves retryable work; an interruption before commit leaves the page to be fetched again. Legacy v1 retains bounded whole-window compatibility: only a complete read can be committed, and oversized windows remain blocked rather than pretending offset pagination is resumable.

Every new traversal rereads the preceding 24 hours. Accounting selects new identities rather than start times after the old checkpoint, so late observations inside this horizon count once. Initial import accounts for all observations in the requested 24-hour window, including baseline history. This does not establish coverage before that window, beyond upstream retention, or for observations arriving more than 24 hours late. A checkpoint older than the supported horizon requires an explicit backfill decision.

## Ledger, privacy and conflicts

Persist an explicit allowlist of identity, attribution, UTC timing, status and nullable measurements. Preserve exact source cost text alongside the numeric presentation value. Never serialize a whole source object: output, status text, user/session attributes and tags are excluded. PII evaluation produces only safe category labels before output is discarded; a failure to prepare those labels prevents committing that page so its content can be refetched. Numeric detector failures retain pending work independently of committed accounting.

An identical fingerprint is a no-op. Changed values for the same immutable v2 identity are ambiguous: quarantine the identity and invalidate its previously trusted bucket contribution. A quarantined identity contributes one unknown observation at its first recorded attribution; other disputed buckets carry conflict coverage without duplicating its call count. The first attribution is retained for bookkeeping, not established as authoritative. Legacy changed copies are also treated conservatively as conflicts until authoritative revision ordering is verified. API/normalization changes require explicit reconciliation rather than silently reinterpreting an existing traversal.

## Materialization and incident identity

Affected hour/agent buckets are rebuilt from ledger records and replaced atomically with completion of the corresponding dirty work. The same connection fence serializes ingestion and materialization. A bounded rebuild that exceeds its supported read limit leaves work pending and health degraded; it cannot publish a truncated total. These totals describe captured observations and retain measurement and conflict coverage. Exact cost text is retained for later reconciliation; the current numeric API remains a rounded operational view, not invoice reconciliation.

Detector work has stable observation and rule identities. Processing waits until the fixed source traversal is exhausted, because descending pages can deliver a candidate before its older baseline. Each observation uses earlier accepted observations available when evaluated as its baseline; the candidate cannot train its own baseline. PII category results are durable without retaining output. Signals distinguish observation and finding kind, so two agents, or two calls by the same agent, in one trace remain visible. Incident insertion is atomic and insert-only: replay cannot reopen a human-resolved incident. Incident persistence and detector-work completion use one transaction. A later measurement conflict annotates existing incident evidence as conflicted without changing its human lifecycle state.

Existing incremental rollups cannot prove observation identity. The new writer must refuse to mix them with ledger-backed totals or silently overwrite them. Existing deployments need an explicit clean database/cutover and bounded source replay; old aggregates stay available for inspection. Automated historical migration and evidence beyond source retention remain open launch work.

## Verification and limits

Unit tests cover deterministic identities, row dispositions, replay, late arrivals, unknown measurements, conflicts, source failure, privacy and distinct incident evidence. Mock tests do not establish atomicity. A fresh localhost-only Mongo replica set must exercise real commit/abort, restart after ingestion, lease takeover, concurrent replay and resolution preservation. A single-node test is not a production failover or durability drill. No customer credentials or source requests are needed for these tests.
